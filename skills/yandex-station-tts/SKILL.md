# yandex-station-tts

Скилл озвучивания текста на Яндекс Станции через локальный Rust CLI
`/home/mrundead/.local/bin/yandex-tts`.

## Команды

### ping (опционально)

Проверка доступности станции / статуса. Только для диагностики, не используется
для озвучивания:

```sh
/home/mrundead/.local/bin/yandex-tts ping
```

### say (основная команда)

Один вызов — одна явная просьба пользователя озвучить текст. Используй `exec`:

```sh
/home/mrundead/.local/bin/yandex-tts say 'Пора гулять с собаками.'
```

## Правила безопасной передачи текста

- Текст передаётся ровно одним аргументом.
- Всегда корректно экранируйте аргумент для shell; никогда не вставляйте
  произвольный текст пользователя в шаблон команды без экранирования.
- Если в тексте есть апостроф, корректно экранируй его для POSIX shell:
  `it's` внутри аргумента записывается как `'it'\''s'`. Не подставляй
  произвольный текст пользователя без shell-экранирования.
- Если инструмент исполнения поддерживает массив аргументов, передай текст
  отдельным элементом `argv` вместо формирования строки команды.

## Ограничения и поведение при ошибках

- Скилл не использует Home Assistant, токены и прямые HTTP-запросы к Яндексу —
  только установленный CLI.
- Вызывайте `say` один раз на каждую явную просьбу пользователя.
- При ошибке НЕ повторяйте вызов автоматически: станция могла уже начать
  воспроизведение, повтор приведёт к дублю озвучки. Сообщите пользователю об
  ошибке и дождитесь явного указания попробовать снова.
- Код выхода `0` означает лишь, что команда принята сервисом; это НЕ гарантия того,
  что звук действительно прозвучал на станции. Не утверждайте пользователю
  факт воспроизведения на основании только exit-кода.
